# RBAC + SSO (API side) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Server-side SSO identity and bank-level RBAC for Hindsight, as an extension package plus three small core patches.

**Architecture:** One package, `hindsight-extensions/rbac/hindsight_ext_rbac`, provides three extension classes:
- a `TenantExtension` that turns a bearer credential (OIDC ID token or `hsp_` API token) into a principal id stored on `RequestContext.tenant_id`;
- an `OperationValidatorExtension` that maps every engine operation to a capability and checks it against the principal's effective role on the bank;
- an `HttpExtension` serving `/ext/rbac/*` for tokens, principals, teams and bank sharing.

RBAC state lives in six tables created by the package's own Alembic tree. The core patches add the acting principal to audit entries, add a validator-visible audit-log read operation, and make MCP tool filtering fail closed.

**Tech Stack:** Python 3.11, FastAPI, asyncpg, PyJWT + cryptography (already server dependencies), aiohttp for JWKS fetches, pytest with the embedded pg0 database.

**Spec:** `docs/superpowers/specs/2026-10-22-rbac-sso-design.md`

**Out of scope here (separate plans):** control plane login and screens (Plan B); image build, prod upgrade and argocd rollout (Plan C).

## Global Constraints

- PostgreSQL only. The RBAC migration uses `run_for_dialect(pg=...)` with no Oracle slot, deliberately.
- Every RBAC table is schema-qualified through `context.config.get_main_option("target_schema")` in the migration and through `fq_table(...)` at runtime.
- `RequestContext.tenant_id` carries the principal identity:
  - an authenticated principal's UUID as a string;
  - the literal `"anonymous"` in optional mode;
  - `None` means a system/internal job.
- `RequestContext.api_key_id` is the token's UUID string for API tokens and `"oidc"` for ID tokens.
- API tokens: `"hsp_" + secrets.token_urlsafe(32)`. Store `sha256(token).hexdigest()` and the first 12 characters as `prefix`. Never log a token or put it in an error message.
- A bank the caller cannot read → reject with **404** `"Bank '<id>' not found"`. Missing capability on a readable bank → **403**.
- A bank with no `rbac_bank_acl` row is treated as private with no owner.
- New banks: `visibility='public'`, `owner_id` = creating principal (NULL if anonymous). Insert with `ON CONFLICT (bank_id) DO NOTHING`.
- Environment variables (the loader turns the part after the slot prefix into lower-cased config keys):
  - `HINDSIGHT_API_TENANT_EXTENSION=hindsight_ext_rbac:RbacTenantExtension`
  - `HINDSIGHT_API_TENANT_AUTH_MODE` = `optional` | `required` (default `required`)
  - `HINDSIGHT_API_TENANT_OIDC_ISSUER` (e.g. `https://accounts.google.com`)
  - `HINDSIGHT_API_TENANT_OIDC_AUDIENCES` (comma-separated client ids)
  - `HINDSIGHT_API_TENANT_ALLOWED_EMAIL_DOMAINS` (comma-separated, e.g. `firefly.ai`)
  - `HINDSIGHT_API_TENANT_ADMIN_EMAILS` (comma-separated)
  - `HINDSIGHT_API_OPERATION_VALIDATOR_EXTENSION=hindsight_ext_rbac:RbacOperationValidator`
  - `HINDSIGHT_API_HTTP_EXTENSION=hindsight_ext_rbac:RbacHttpExtension`
  - `HINDSIGHT_API_EXTENSION_PASSTHROUGH_HEADERS=user-agent,x-forwarded-for` (needed for anonymous logging)
- Core files touched, and only these:
  - `hindsight_api/api/http.py`: the audited wrapper;
  - `hindsight_api/mcp_tools.py`: filter fail-closed and MCP audit actor;
  - `hindsight_api/extensions/operation_validator.py`: one enum member;
  - `hindsight_api/engine/memory_engine.py`: three audit-read methods.
  
  Mark every core edit with a `# fork(rbac):` comment so upstream merges show them.
- Follow `hindsight-api-slim` conventions: run `./scripts/hooks/lint.sh` before each commit; no raw dicts for structured data that crosses module boundaries (use dataclasses); type annotations everywhere.

## Review Focus

1. **Alias bypass:** reading a private bank through one of its aliases must 404 for a non-member, exactly like the canonical id. Test in Task 6.
2. **Token right after disable:** a token whose principal was disabled one request ago must 401 on the next request (no caching of principal state across requests). Test in Task 5.
3. **Clone/export of a private bank by a non-member:** must 404, and must not create the target bank. Test in Task 6.
4. **Concurrent first creates by two principals:** exactly one becomes owner, the other gets normal Writer access on the (public) bank, and nobody gets a 500. Test in Task 6.
5. **Invalid token in optional mode:** a request carrying a garbage bearer gets 401, never anonymous access. Test in Task 5.

- Produces, in `policy.py`:

  - `class Role(StrEnum)`: `READER="reader"`, `WRITER="writer"`, `OWNER="owner"` (ordered by `ROLE_RANK = {READER: 1, WRITER: 2, OWNER: 3}`)
  - `@dataclass(frozen=True) class Principal`: `id: str`, `kind: Literal["user", "service", "anonymous"]`, `is_admin: bool`, `email: str | None`, `name: str`
  - `ANONYMOUS = Principal(id="anonymous", kind="anonymous", is_admin=False, email=None, name="anonymous")`
  - `@dataclass(frozen=True) class BankAcl`: `bank_id: str`, `visibility: Literal["private", "public"]`, `owner_id: str | None`
  - `def effective_role(principal: Principal, acl: BankAcl | None, grant_roles: Iterable[Role]) -> Role | None`
  - `def capabilities(principal: Principal, acl: BankAcl | None, role: Role | None) -> frozenset[Capability]`
  - `READ_OP_CAPABILITY: dict[BankReadOperation, Capability]`, `WRITE_OP_CAPABILITY: dict[BankWriteOperation, Capability]`, `MCP_TOOL_CAPABILITY: dict[str, Capability]`

Rules for `effective_role`:
- A principal with `is_admin` gets `OWNER`.
- `acl is None` and not admin gives `None`.
- If `owner_id == principal.id`, the role is `OWNER`.
- Otherwise take the highest grant role.
- A public bank adds an implicit `WRITER` for every principal, anonymous included.
- Return the maximum of all of these, or `None`.

Rules for `capabilities`:
- `READER` → `{READ}`; `WRITER` → `{READ, WRITE}`; `OWNER` → `{READ, WRITE, MANAGE}`.
- `DELETE_BANK` is added for admins, and for `OWNER` when `acl.visibility == "private"`.

Operation maps:
- `READ_OP_CAPABILITY` maps every `BankReadOperation` member to `READ`, except `LIST_WEBHOOKS`, `LIST_WEBHOOK_DELIVERIES` and `LIST_AUDIT_LOGS`, which map to `MANAGE`. `LIST_AUDIT_LOGS` is added in Task 8; reference it via `getattr` until then.
- `WRITE_OP_CAPABILITY` maps `CREATE_WEBHOOK`, `UPDATE_WEBHOOK` and `DELETE_WEBHOOK` to `MANAGE`, `DELETE_BANK` to `DELETE_BANK`, and every other member to `WRITE`.
- `MCP_TOOL_CAPABILITY`:
  - `delete_bank` → `DELETE_BANK`;
  - these tools → `READ`: `recall`, `reflect`, `list_banks`, `list_mental_models`, `get_mental_model`, `list_directives`, `list_memories`, `get_memory`, `list_documents`, `get_document`, `list_operations`, `get_operation`, `list_tags`, `get_bank`, `get_bank_stats`, `get_knowledge_base_tree`, `search_knowledge_base`, `get_knowledge_page`;
  - every other tool in `hindsight_api.mcp_tools._ALL_TOOLS` → `WRITE`.

### Task 4: Credential verification

**Files:**
- Create: `hindsight-extensions/rbac/hindsight_ext_rbac/identity.py`
- Test: `hindsight-extensions/rbac/tests/test_identity.py` (no database)

**Interfaces:**
- Produces:
  - `def hash_token(token: str) -> str` (sha256 hex)
  - `def is_api_token(credential: str) -> bool` (`startswith("hsp_")`)
  - `@dataclass(frozen=True) class OidcIdentity`: `email: str`, `name: str`
  - `class OidcVerifier`:
    - constructor `OidcVerifier(issuer: str, audiences: list[str], allowed_domains: list[str])`
    - `async def start()` and `async def close()`, which own an `aiohttp.ClientSession`
    - `async def verify(token: str) -> OidcIdentity`
  - `class CredentialError(Exception)`, whose message is safe to return to the caller

`verify` must:
- discover `jwks_uri` from `{issuer}/.well-known/openid-configuration`;
- cache keys by `kid` for 1 hour, and refetch at most once per 60 seconds on an unknown `kid` (the supabase-tenant extension shows the pattern);
- accept `RS256` only;
- require `iss == issuer` (Google also issues `accounts.google.com` without a scheme, so accept both when the issuer is `https://accounts.google.com`);
- require `aud` in `audiences`, a valid `exp`, `email_verified is True`, and an email domain (the part after `@`, lower-cased) in `allowed_domains`.

**Interfaces:**
- Consumes the policy (Task 1) and the store (Task 3).
- Produces `class RbacOperationValidator(OperationValidatorExtension)` with a single gate:
  `async def _require(self, bank_id: str, request_context: RequestContext, capability: Capability, what: str) -> ValidationResult`. It:
  - resolves the principal:
    - `tenant_id is None` with `request_context.internal` → system: accept;
    - `tenant_id is None` without `internal` → reject 401 "Missing credentials";
    - `"anonymous"` → `ANONYMOUS`;
    - otherwise `store.get_principal`; `None` → reject 401;
  - loads `acl` and `grant_roles`;
  - rejects with **404** when the caller lacks `READ`, and with **403** `"You need <capability> on bank '<id>' to <what>"` when the caller has `READ` but lacks the capability;
  - logs at WARNING `rbac.anonymous op=<what> bank=<id> ip=<x-forwarded-for> ua=<user-agent>`, using `request_context.extra_headers`, when the principal is anonymous.

Hook mapping:
- `validate_retain` → `WRITE`
- `validate_recall`, `validate_reflect` → `READ`
- `validate_consolidate` → `WRITE`
- `validate_mental_model_get` → `READ`; `validate_mental_model_refresh` → `WRITE`
- `validate_memory_update` → `WRITE`
- `validate_bank_read` → `READ_OP_CAPABILITY[ctx.operation]`
- `validate_bank_write` → `WRITE_OP_CAPABILITY[ctx.operation]`
- `validate_import` → `WRITE` on `ctx.bank_id`; if no ACL row exists yet (a restore into a new bank), accept, because create already ran.
- `validate_create_bank`:
  - an unauthenticated non-system caller (`tenant_id is None`, not internal) → 401;
  - otherwise, if an ACL row exists for `ctx.bank_id` and the caller can't read it → 404;
  - else `record_new_bank(ctx.bank_id, owner_id=None if anonymous or system else principal.id)` and accept.
- `bank_list_scope`:
  - admin or system → `BankListScope(bank_ids=None)`;
  - anonymous → the ids of public banks (store query `readable_bank_ids("anonymous")` handles anonymous by returning public only);
  - else `BankListScope(bank_ids=await store.readable_bank_ids(principal.id))`.
- `filter_mcp_tools` → `frozenset(t for t in tools if MCP_TOOL_CAPABILITY.get(t) in caps)`, plus `list_banks` and `create_bank` for any authenticated or anonymous caller; `frozenset()` when the caller cannot read the bank.
- `precheck` keeps the default (accept).

| PUT / DELETE | `/teams/{id}/members/{principal_id}` | admin | 204 |
